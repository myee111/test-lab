= Author the Playbook

Now for the part Scott said would take all week. You're going to describe the entire web service in one small YAML file, using the `podman` system role to deploy it.

== Create the project directory

Keeping the playbook in its own directory makes it easy to find, version, and hand to the next person.

[source,bash,run]
----
mkdir -p ~/podman-lab
----

== Write the playbook

Create `~/podman-lab/playbook.yml` with the following content — paste the whole block into the terminal.

[source,bash,run]
----
cat > ~/podman-lab/playbook.yml << 'EOF'
---
- name: Deploy a secure nginx web server
  hosts: localhost
  become: true
  tasks:
    - name: Create the web content
      ansible.builtin.copy:
        content: |
          <h1>Super-Business internal web server</h1>
          <p>Served by a systemd-managed nginx container.</p>
        dest: /opt/web/index.html
        mode: '0644'
    - name: Manage the nginx quadlet with the podman system role
      ansible.builtin.include_role:
        name: redhat.rhel_system_roles.podman
      vars:
        podman_quadlet_specs:
          - name: nginx
            type: container
            file_content: |
              [Container]
              Image=registry.access.redhat.com/ubi10/nginx-126:10.0
              PublishPort=8080:8080
              PodmanArgs=--security-opt no-new-privileges
              Exec=/usr/libexec/s2i/run
              Volume=/opt/web/index.html:/opt/app-root/src/index.html:Z
        podman_firewall:
          - port: 8080/tcp
            state: enabled
EOF
----

That's the whole service — a web page, a Quadlet, and a firewall rule, all declared in one reviewable file. Let's walk through what each part does before you run it.

=====
The play starts with the header — which host runs the playbook and whether it needs root.

.The play header
[%collapsible]
====

[source,yaml]
----
- name: Deploy a secure nginx web server
  hosts: localhost
  become: true
----

* `hosts: localhost` — apply this on the machine you're logged into. In bigger estates you'd point this at a group of hosts from an inventory and deploy the same service everywhere at once.
* `become: true` — the playbook writes files under `/opt` and installs a Quadlet under `/etc/containers/systemd/`, which needs root.

====
=====

=====
The container ships without a web page, so the first task puts one on disk.

.Creating the web content
[%collapsible]
====

[source,yaml]
----
    - name: Create the web content
      ansible.builtin.copy:
        content: |
          <h1>Super-Business internal web server</h1>
          <p>Served by a systemd-managed nginx container.</p>
        dest: /opt/web/index.html
        mode: '0644'
----

The nginx container image ships an empty web root — it's built as a base for your own content. This task writes a simple page to `/opt/web/index.html` on the host, which the Quadlet then mounts into the container. On the job, `/opt/web/` is where you'd drop the real site.

====
=====

=====
The single role include passes the `podman` system role everything you want.

.Including the podman system role
[%collapsible]
====

[source,yaml]
----
    - name: Manage the nginx quadlet with the podman system role
      ansible.builtin.include_role:
        name: redhat.rhel_system_roles.podman
----

This is the supported Red Hat role you installed in module 2. You don't write the tasks that pull images, write Quadlet files, or talk to systemd — the role does all of it. Your job is only to *declare what you want* in `vars`.

====
=====

=====
The Quadlet specification is where the service itself gets defined.

.The Quadlet specification
[%collapsible]
====

[source,yaml]
----
        podman_quadlet_specs:
          - name: nginx
            type: container
            file_content: |
              [Container]
              Image=registry.access.redhat.com/ubi10/nginx-126:10.0
              PublishPort=8080:8080
              PodmanArgs=--security-opt no-new-privileges
              Exec=/usr/libexec/s2i/run
              Volume=/opt/web/index.html:/opt/app-root/src/index.html:Z
----

`podman_quadlet_specs` is a list of Quadlet unit files for the role to manage. This one is named `nginx` with type `container`, so the role writes it to `/etc/containers/systemd/nginx.container`. That single file generates the systemd service `nginx.service`.

The `[Container]` section is the Quadlet itself:

* `Image=` — a *fully qualified* image name with a pinned tag, from Red Hat's signed registry (`registry.access.redhat.com`). `ubi10/nginx-126` is the nginx built for RHEL 10, pinned to the `10.0` tag. Fully qualified + pinned is deliberate: you know exactly what you're running, you get Red Hat's signed, scanned image, and podman needs the full reference to check for updates later.
* `PublishPort=8080:8080` — publish container port 8080 on host port 8080. The nginx image is built to run as a non-root user *inside* the container, so nginx listens on unprivileged port 8080.
* `PodmanArgs=--security-opt no-new-privileges` — the container's processes can't gain extra privileges via setuid or file capabilities. One line, and a whole class of container escapes is off the table.
* `Exec=/usr/libexec/s2i/run` — the image's *default* command just prints usage help and exits (it's a source-to-image builder base). `Exec=` tells systemd to run the image's start script instead, which wires logs to stdout and launches nginx in the foreground.
* `Volume=/opt/web/index.html:/opt/app-root/src/index.html:Z` — mount the page you created into the container's web root. The `:Z` tells podman to label the file for SELinux so the container can read it.

[NOTE]
====
Look at the security story you got for free: a pinned, signed image from a trusted registry; a container that runs as a non-root user; no privilege escalation. And you didn't hand-tune any of it — it's declared, reviewable code.
====

====
=====

=====
One variable opens the port in the host firewall.

.Opening the firewall port
[%collapsible]
====

[source,yaml]
----
        podman_firewall:
          - port: 8080/tcp
            state: enabled
----

The same role can also open the port in the host firewall, using the `firewall` system role under the hood. One variable, and the port is reachable from other machines — no `firewall-cmd` incantations to remember.

====
=====

== What the role will do when it runs

When you run this playbook, the `podman` system role will:

1. Write `/etc/containers/systemd/nginx.container` from your `file_content`
2. Reload systemd, which generates `nginx.service` from the Quadlet
3. Pull `registry.access.redhat.com/ubi10/nginx-126:10.0`
4. Start the service, which mounts your page, publishes port 8080, and launches nginx
